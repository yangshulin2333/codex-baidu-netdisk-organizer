# 百度网盘整理工作流

在进行全盘盘点、分类设计、重复分析或多批整理时阅读本文件。

## 1. 锁定范围和保护规则

先让用户说明人物、设备、业务资料和优先级。把结果分为：

- 明确保留：照片、相机视频、聊天记录、证件及用户指定资料。
- 可整理：归属明确但目录结构或命名混乱的内容。
- 删除候选：用户明确表示低价值，且已完成路径和内容核对的内容。
- 待确认：所有权、内容、唯一性或重要性不明确的内容。

不要从设备型号、用户名或文件夹名称推断所有权。用户只允许处理自己的资料时，其他人物目录必须排除；归属不明则待确认。

## 2. 只读盘点

从用户授权的云盘范围读取，不扫描电脑本地目录代替云盘：

1. `get_quota` 获取容量背景。
2. `file_list` 查看一级结构。
3. `media_list_all` 分页递归读取大目录；记录游标或 `start`，避免漏页和重复计数。
4. `file_meta` 每次最多 10 个 FSID，用于补充 MD5、时间、尺寸、缩略图或下载信息。
5. 必要时使用关键词或语义搜索，但说明语义索引可能不完整。

报告扫描根、页数、项目数、字节数、扩展名和无法读取的范围。抽样查看内容不能表述为已经理解所有文件。

## 3. 分类和命名方案

优先使用稳定、可解释的维度：资料归属、生活/工作/资源、事件或项目、年份、来源设备。不要为了整齐建立过深层级，也不要在未识别内容时批量重命名。

方案至少列出：

- 当前完整路径和拟议目标路径。
- 文件/目录数量和容量。
- 归类依据及信心。
- 同名冲突、受保护项和待确认项。
- 本批是否仅创建目录、移动、重命名或包含删除。

先做高确定性、可回读的移动；重命名放在内容确认之后；删除单独成批。

## 4. 重复候选

证据强度从高到低：

1. 同一文件哈希且大小一致：精确重复候选。
2. 媒体内容指纹或人工视觉核对：近似重复候选。
3. 同名同大小：弱线索。
4. 仅同名、相似名称或相邻时间：不能证明重复。

即便是精确重复，也先选定保留副本，比较路径语义、时间、元数据和是否属于重要照片/聊天记录。近似照片、连拍、编辑版、压缩版和聊天转存图不得自动删除。

## 5. Prepare、确认和执行

按操作类型拆分计划；一个计划不要混合创建、移动、重命名和删除。调用相应 prepare 后，完整展示：

- `plan_id`、过期时间和操作类型。
- 全部项目及目标。
- 汇总文件数、目录数和字节数。
- 预检发现的冲突或状态变化。
- `confirmation_required` 原文。

等待用户在当前消息中原样回复确认码。收到后只执行该计划一次。上一批 `verified_success` 后才能准备下一批，避免使用过期快照。

## 6. 验收和交接

每批记录：

- 执行计划和确认码前缀，不记录凭据。
- 远端是否报告错误。
- 源路径是否消失、目标路径是否存在、FSID 是否匹配。
- 成功、失败或未知项目清单。
- 后续仍待处理、明确排除和必须由用户决定的内容。

遇到部分失败、超时或连接中断时停止连续操作，重新只读盘点。不要仅凭接口返回成功就声称整理完成，也不要因计划已准备而声称文件已修改。

此时持久写入隔离应保持生效。只读确认现状并完成交接后，提示用户本人按恢复文档在本机手工解除；Agent 不得调用解除隔离脚本，也不得自动重放原计划。
